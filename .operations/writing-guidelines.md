# Writing guidelines

1. **Simple over exhaustive.** A practice is one idea an agent author can apply in a morning.
2. **Checkable.** Every practice ends with how to check it. A practice with no check is advice, and
   belongs in prose elsewhere.
3. **Evidence.** Link a source, or write "From practice" and describe the failure that motivated it.
   Do not quote what you have not read.
4. **Agent-specific.** The practice must matter more for an agent caller than for a person. General
   CLI advice goes to clig.dev.
5. **Tool-neutral.** Examples use the made-up tool `acme`. No real product, company, host, ticket key
   or repository in examples.
6. **One template.** New deep dives copy [sections/template.md](../sections/template.md). The
   README entry has a TL;DR, an Otherwise, a Do and a Don't (always both, even when one line), and a
   Check.
7. **Numbered and counted.** Sections and items are numbered; keep the counts in the table of contents
   in step.
8. **Tags.** `#strategic` shapes the design, `#advanced` needs infrastructure, `#security` concerns an
   untrusted caller.
9. **Disagree openly.** When a practice contradicts a well-known source, say so and say why.
